# Suthep — A Developer's World

พอร์ตโฟลิโอเล่าเรื่องภาษาไทย ผ่านโลก 3D สี่บท: พื้นดิน → ภูเขา → ท้องฟ้า → อวกาศ

## เริ่มใช้งาน

ต้องมี Node.js 22.12+ หรือ 24+

```sh
npm install
npm run dev
```

เปิด URL ที่ Vite แสดงใน terminal (ปกติ http://127.0.0.1:5173)

```sh
npm run build
npm run preview
```

นำโฟลเดอร์ `dist` ไปโฮสต์บน static hosting ได้ เช่น Vercel หรือ Netlify โดยตั้ง build command เป็น `npm run build` และ output directory เป็น `dist`

- `src/Journey.tsx` — โลก low-poly ฉากเดียวแบบต่อเนื่อง สร้างด้วย Three.js เป็นเสาแนวตั้ง: เกาะ กระท่อม โต๊ะทดลอง → ภูเขาพร้อมทางเดิน ธงไมล์สโตน เต็นท์ → เมฆ บอลลูน เกาะลอย เครื่องบินกระดาษ → ดาวเคราะห์ จรวด ดาวเทียม ดาว กล้องไต่ขึ้นตามการเลื่อนหน้า พื้นหลังไล่สีตามระดับความสูง มี "นักวิ่ง" ตัวเล็กหนึ่งตัวเดินทางตลอดเรื่อง: ออกจากประตูกระท่อม วิ่งรอบเกาะ ไต่บันไดหินขึ้นยอดเขา กระโดดข้ามเมฆและเกาะลอย แล้วลอยตัว (ใส่หมวกอวกาศ) ผ่านดาวเคราะห์ไปหาจรวดและดาวเทียม ตำแหน่งผูกกับค่า progress ของกล้องที่ผ่าน easing เดียวกัน (`route` ในไฟล์) จึงเคลื่อนที่ลื่นตามการเลื่อนและอยู่ในแถบฉากที่โผล่เหนือการ์ดเนื้อหาเสมอ ท่าวิ่ง/กระโดด/ลอยคำนวณจากระยะทางที่เคลื่อนจริง ไม่ใช่เวลา บันไดหินบนภูเขาเป็นทางสลับฟันปลา (switchback) บนหน้าเขาที่หันเข้ากล้อง มีแคมป์ 8 จุดตามหมวดใน `data/skillCategories.ts` ทุกเฟรมที่เรนเดอร์จะ project ตำแหน่งแคมป์เป็นพิกัดจอ แล้วเขียน transform/opacity ให้การ์ด HTML (`.skill-card`) โดยตรง การ์ดใช้หน้าตาเดียวกับป้าย TOOLKIT (แผงโปร่ง eyebrow เป็น path ของหมวด + หัวข้อ + ชิป) โผล่ทันทีตามตำแหน่งเลื่อน (ไม่ผ่านการหน่วงเวลา) ทีละคู่ (แคมป์ซ้าย+ขวา = 1 จุดพัก รวม 4 จุด) แต่ละคู่ผูกกับค่า altimeter (`cardAltitudes` = 470 / 600 / 710 / 910 M) โผล่เต็มที่ค่านั้นและ fade เข้าในช่วง 20 M ก่อนหน้า การ์ดที่เคยแสดงแล้วจะค้างไว้เมื่อเลื่อนกลับขึ้นตลอดช่วงภูเขา (คู่ที่อยู่เหนือตำแหน่งปัจจุบันหรี่เหลือ 40%) และจางออกเมื่อเลื่อนกลับเข้า hero ต่ำกว่า 430 M (บนจอแคบค้างเฉพาะคู่แรก เพราะวางได้ทีละคู่) นักวิ่งตามไปแตะแคมป์ทีละจุด (ราว 50 M ต่อแคมป์) แล้วเดินต่อถึงยอดที่ราว 1,900 M แล้วนักวิ่งค่อยไต่ตามมาแตะแคมป์ทั้งสองของคู่ ภูเขาสูง 14 หน่วย (สูงขึ้น 40%) ทางแกว่งซ้ายขวาเพียง 0.27 เรเดียน แคมป์ทั้ง 8 อยู่ครึ่งล่างของเขา (ห่าง 1.15 หน่วย) เส้นทางเดินยาวราว 19 หน่วย (ครึ่งหนึ่งของแบบแรก) ส่วนท้องฟ้าและอวกาศถูกยกขึ้นตามในกลุ่ม `upper` บน desktop เห็นคู่ปัจจุบันและคู่ก่อนหน้า คู่เก่ากว่านั้นจางลง การ์ดแต่ละใบถูกผลักออกจากทางเดินเพิ่มอีก `spread` px (สูงสุด 135 px บนจอกว้าง ลดตามความกว้างจอ และ 0 บนมือถือ) เพื่อให้ฝั่งซ้าย-ขวาห่างกันชัด บนจอแคบการ์ดซ้ายและขวาของคู่เดียวกันถูกจำกัดให้อยู่คนละครึ่งจอจึงไม่ชนกัน การ์ดฝั่งเดียวกันจัดวางจากใบใหม่สุดก่อน: ใบที่กำลังโผล่อยู่ตรงแคมป์ของมัน ใบเก่ากว่าถูกเลื่อนลงไปต่อท้าย (หรือย้ายไปคอลัมน์นอกเมื่อจอกว้างพอ) และใบเก่าที่ถูกดันพ้นขอบล่างจะจางออกตามระยะที่ล้น (ไม่ตัดหายทันที) ใบที่กำลังโผล่จะจองพื้นที่ทีละน้อยตามความโปร่งใสของมัน ใบเก่าจึงเลื่อนลงอย่างต่อเนื่องแทนการกระโดด และความสูงการ์ดถูกวัดไว้ล่วงหน้าตอน resize ไม่อ่าน layout ทุกเฟรม และความโปร่งใส/สเกลของแต่ละใบตามค่าที่สกรอลล์กำหนดด้วย easing ตามเวลา (~180 ms) เพราะหน้าต่างเฟด 20 M บนมือถือเท่ากับการเลื่อนเพียงสิบกว่าพิกเซล การโผล่และการดันการ์ดอื่นจึงลื่นเสมอ (โหมดลดการเคลื่อนไหวเป็นทันที) จึงไม่ทับกันและไม่กระตุกในทุกความสูงจอ คู่ถัดไปเริ่มโผล่ได้ต่อเมื่อคู่ก่อนหน้าโผล่เต็มแล้ว การ์ดทั้งหมดจางออกช่วงท้ายทางเดิน (progress 0.94–0.99) ก่อนหัวบทภูเขาเข้าจอ เพราะหัวบท 02, 03 และ 04 (`.chapter-intro`: ป้ายบท หัวข้อ คำอธิบาย/ป้ายสถานะ) ลอยอยู่บนฉาก 3D โดยไม่มีแผง แต่ละก้อนข้อความมีพื้นหลังโปร่งแสงของตัวเอง (บทอวกาศใช้โทนมืดและชิดซ้ายบนเดสก์ท็อป) ส่วน timeline รายการโปรเจกต์ ย่อหน้าติดต่อ รูป และ footer ยังอยู่ในแผง `.chapter-content` เหมือนเดิม บนจอแคบเห็นทีละคู่ การ์ดที่ chips ห่อเกิน 2 แถวที่ความกว้างพื้นฐาน (236px) จะกว้างขึ้น 70% (วัดจำนวนแถวจริงตอน resize และหลังฟอนต์โหลด) โดยลดสัดส่วนลงถ้าจอไม่พอสำหรับการ์ดกว้างสองใบเคียงกัน และไม่ขยายบนมือถือ layout ใช้ความกว้างรายใบ จึงยังไม่ทับกัน
- `src/Traveler.ts` และ `src/journey.ts` — ตัวละครขนาด 1.5 เท่า พร้อมชุดตามความสูงที่แสดง: นักศึกษา (รวมช่วง 80 M), วัยทำงานตั้งแต่ 1,120 M, สูทสุภาพตั้งแต่ 5,510 M ต่อเนื่องถึง 33,640 M และก่อนเปลี่ยนชุดอวกาศ ชุด ผม รองเท้า และกระเป๋าใช้ geometry ที่เก็บไว้ล่วงหน้า สลับกลับได้เมื่อเลื่อนย้อนขึ้น เครื่องบิน/แคปซูลและอุปกรณ์บนตัวใช้สเกลเดียวกัน แถบสถานะแสดงช่วงชีวิตและขยายปุ่มเป็น 48px พร้อมจัดข้อความให้พอดีมือถือ
- `src/Flourish.ts` — GSAP + ScrollTrigger (ฟรีทั้งหมดตั้งแต่ปี 2024): ScrollTrigger scrub timeline ของการเดินทาง (ขอบเขตของแต่ละบท → progress 0–3.7 แบบ piecewise-linear โดยใช้เส้นอ้างอิง 38% ของความสูงจอ) และสร้าง timeline ใหม่อัตโนมัติเมื่อ layout เปลี่ยน แทน scroll listener ที่เขียนเอง ส่วนการเคลื่อนไหวตกแต่งใช้ GSAP tween: บอลลูน/เกาะลอย/ดาวเทียมลอยขึ้นลงไม่พร้อมกัน เมฆลอยตามจังหวะของตัวเอง ธงสะบัดสลับกัน ป้ายแคมป์และธงไมล์สโตน/ยอดเขา pop ด้วย elastic ease ตอนนักวิ่งไปถึง (ครั้งเดียวต่อการผ่านขาขึ้น ไม่ยิงตอนเปิดหน้ากลางทาง) และ timeline การกระโดดของนักวิ่ง (ย่อตัว → พุ่งขึ้น → ตก → ย่อรับ → คืนตัว) ที่ถูก scrub ตามสกรอลล์ ให้ทั้งความสูงของโค้งและ squash/stretch ของตัวละคร root timeline ของ GSAP ถูกถอดจาก ticker ของมันเองแล้ว tick จากลูปเฟรมของ Journey (rAF เดียว) ด้วยนาฬิกาที่เดินเฉพาะตอนไม่พัก จึงหยุดและเล่นต่อจากจุดเดิมเมื่อผู้ใช้เลือกลดการเคลื่อนไหว ทุก tween และ ScrollTrigger ถูกล้างด้วย `gsap.context` ตอน unmount
- `src/Weather.ts` — สภาพอากาศตามระดับความสูงที่แสดงบนหน้าจอ: ฝน 210–1,120 M และหิมะพร้อมลม 1,120–2,950 M (ค่อย ๆ จางช่วง 2,800–2,950 M) ปรับขอบช่วงได้ที่ `weatherBands` ฝนชนสามเหลี่ยมพื้นภูเขา/เกาะที่สุ่มด้วย raycast ครั้งเดียวตอนเริ่มฉาก หยดน้ำกระเด็นและวงน้ำใช้จังหวะเดียวกับฝน พื้นเปียกค่อย ๆ แห้ง ส่วนทางน้ำเชื่อมแม่น้ำอยู่ใน `MountainWater.ts` อนุภาคอากาศเคลื่อนใน shader ใช้สูงสุด 5 draw calls และลดจำนวนบนมือถือ ลมกระโชกขับหิมะ เส้นลม ต้นไม้ เมฆ และการเอียงตัวต้านลมของนักวิ่งจากนาฬิกาเดียวกัน พร้อมลดแสงและเปลี่ยนเป็นโทนเย็น รองรับการหยุดภาพเคลื่อนไหวและการเลื่อนย้อนกลับ
- `src/MountainWater.ts` — ทางน้ำจากจุดรับฝนจริง: สร้างดัชนีสามเหลี่ยมและหาเส้นทางลงเขาครั้งเดียวตอนเริ่มฉาก โดยรวมแรงโน้มถ่วงกับทิศฝน/ลม รับเฉพาะทางที่ต่อถึงแม่น้ำ (สูงสุด 22 ทางบนเดสก์ท็อป / 12 ทางบนมือถือ) shader สุ่มจุดต้นน้ำและจังหวะ แล้วให้หน้ากระแสเดินทางลงเขา แม่น้ำโค้งต่อเนื่องถึงน้ำตก มีระลอก รอยฝน ฟอง และก้อนหินริมตลิ่ง ความเร็วแม่น้ำเพิ่มตามน้ำที่มาถึงและค่อย ๆ ลดหลังฝนหยุด ใช้ 4 draw calls ไม่มี raycast หรือการสร้าง geometry ระหว่างเล่น และหยุดเวลาเดียวกับฉากเมื่อพักภาพเคลื่อนไหว
- `src/journeyMath.ts` — คณิตศาสตร์แปลงตำแหน่งสกรอลล์เป็นความคืบหน้าของบท ความสูง (altimeter) และเส้นโค้งการเดินทาง ใช้ร่วมกันโดย App และ Journey
- **โปรไฟล์คุณภาพบนมือถือ** (`mobile` ใน Journey: จอ ≤800px หรือ pointer แบบสัมผัส) เรนเดอร์ที่ pixel ratio 1, เงาแบบ PCF ธรรมดา shadow map 512, ให้เฉพาะภูเขาและนักวิ่ง cast เงา (วัตถุอื่นยังรับเงา) และปิดเงาของไฟ key light ของนักวิ่ง ทำให้พิกเซลที่ต้องเรนเดอร์ลดราว 3 เท่าเทียบกับโปรไฟล์เดสก์ท็อปที่ framing เดียวกัน และ shadow caster ลดจาก ~113 เหลือ ~20 (ดูได้จาก `journeyDiagnostics` ตอน dev) เดสก์ท็อปยังใช้ pixel ratio 1.75 + PCFSoft 1024 เหมือนเดิม
- `src/style.css` — สี ฟอนต์ layout และ responsive styles บนจอ ≤800px ปิด `backdrop-filter` ทุกจุดที่ทับ canvas (header, แผงบท, การ์ด, สถานะ) และใช้พื้นทึบขึ้นเล็กน้อยแทน เพราะ blur ทับ WebGL บังคับให้เบราว์เซอร์อ่านเฟรมกลับมาเบลอใหม่ทุกเฟรม เป็นสาเหตุหลักของอาการกระตุกบนมือถือ

การ์ดโปรเจกต์ใช้ภาพหน้าจอจริงจาก `public/project-web/thumbs` (โหลดแบบ lazy) และเมื่อเปิดรายละเอียดจะมีแกลเลอรีเลื่อนดู `slideImages` ทั้งหมดจาก `public/project-web` โปรเจกต์ที่ไม่มีภาพหน้าจอ (เช่น API แบ็กเอนด์) ยังใช้ concept visual ที่สร้างด้วย CSS เหมือนเดิม ภาพ hero ของเจ้าของเว็บถูกตัดพื้นหลังดำออกให้โปร่งใสโดยสคริปต์ จึงวางบนพื้นหลังสีใดก็ได้

ฉาก 3D เรนเดอร์ครั้งเดียวเป็นพื้นหลังแบบ fixed แล้วเนื้อหาเลื่อนซ้อนด้านบน ระหว่างบทมีช่วง "เดินทาง" (`.travel`) ให้กล้องไต่ขึ้นและสีพื้นหลังเปลี่ยน (ครีม → เขียวหมอก → ฟ้า → น้ำเงินเข้มพร้อมดาว) header, rail และแคปซูลสถานะเปลี่ยนธีมตามบทผ่าน `data-chapter` บนมือถือเนื้อหาอยู่บนแผงกระจกโปร่งเพื่อให้ยังเห็นฉาก รองรับ pointer parallax, ปุ่มพักภาพเคลื่อนไหว, `prefers-reduced-motion`, หยุดเรนเดอร์เมื่อแท็บถูกซ่อน และมี fallback เมื่ออุปกรณ์ไม่รองรับ WebGL เนื้อหาหลักยังอ่านได้ตามปกติ

ฟอนต์โหลดจาก Google Fonts และมี system fallback หากไม่มีอินเทอร์เน็ต ไม่มี backend, analytics หรือการส่งข้อมูลส่วนตัวผ่านฟอร์ม ปุ่มติดต่อใช้ mailto และลิงก์ตามข้อมูลที่ให้มา
